## 1. 为什么是 21 次而不是 18 次

非线性增量（Murnaghan − 线性）只有位移的万分之一左右。两次运行只要模型实现有一点不同，比如网格、积分或载荷写法，差异就可能和增量一样大。所以**同一工况的线性和非线性必须出自同一份模型源码**。

已完成的 3 次线性运行用的源码（SHA-256 `d36366…`）没有归档。仓库里归档的源码 `research/comsol-p1-20261024/UltraResearch.java`（`c7140d6c…`）是另一份，本构自检就是用它通过的。因此：

- 用归档源码把三个线性基准**重算一次**，与 Murnaghan、StVK 配对使用。
- 旧的三个线性结果保留下来，用于复现检查：新旧线性结果应一致到 1e-6 以内。

## 2. 推荐做法：用运行包直接跑

运行包里的模型完全由源码和输入决定，不需要在图形界面里建模。剩余运行有两种做法，作业完全相同：

- 继续用归档的修正版运行包 `serendipity-54e90010/P1_SERP_20261102.zip`。包内的 `run-gated.ps1` 会在瞬态计算前先检查本构和网格。
- 或由仓库重新生成，只生成剩余的层级 2–4：

```sh
python research/comsol-p1-20261024/local_kit.py build --output p1-kit --tiers 2 3 4
```

生成的 `p1-kit/` 含所选层级的作业文件夹、作业清单 `jobs.json` 和运行脚本。Windows 上：

```powershell
.\run-all.ps1 -ComsolBin "C:\Program Files\COMSOL\COMSOL64\Multiphysics\bin\win64" -Tier 2,3
```

脚本在每个文件夹里执行 `comsolcompile UltraResearch.java` 和 `comsolbatch -inputfile UltraResearch.class -batchlog solver.log`。已完成的作业会自动跳过，中断后重新执行同一条命令即可续跑。不要改动作业文件夹里的源码和输入，改动后哈希对不上，结果无法收集。

## 4. 模型设置（与已完成运行一致）

自己在图形界面里建模时，必须逐项满足下表；用运行包则自动满足。

| 项目 | 基准 | dt2 | mesh2 |
|---|---|---|---|
| 单元 | 四阶 serendipity 六面体（`shnserp`），扫掠网格 | 同基准 | 同基准 |
| 单元尺寸 | x 0.8 mm（60 个），y 2/3 mm（3 个），z：T=1.6 时 0.8 mm（2 层），T=2.0 时 2/3 mm（3 层） | 同基准 | 目标 h = 0.56 mm |
| 单元数 / 自由度 | A、B：360 / 22167；C：540 / 30711 | 同基准 | 约 3 倍 |
| 积分阶次 | 20 | 20 | 20 |
| 时间积分 | 广义 α，ρ∞ = 1，输出时刻严格命中（strict），初始步长 = 最大步长 | 同基准 | 同基准 |
| 最大步长 | 0.01 μs | **0.005 μs** | 0.01 μs |
| 容差 | 相对 1e-6；绝对 1e-18 m，非缩放（unscaled） | 同基准 | 同基准 |
| Newton | 全耦合，每个时间步更新一次 Jacobian，容差因子 0.001，最多 12 次迭代，不按残差终止 | 同基准 | 同基准 |
| 记录 | 0–30 μs，每 0.05 μs 一个时刻，共 601 个 | 同基准 | 同基准 |

三种本构用同一模型，通过两个开关切换：
- linear：几何非线性和材料三阶项都关闭。
- stvk：只打开几何非线性。
- murnaghan：两者都打开。

## 5. 输出要求

- **用运行包时：** 每个作业文件夹会生成：
  - `completed.properties`：运行回执，含网格、自由度、耗时。
  - `coarse.csv`（基准）、`timecheck.csv`（dt2）或 `fine.csv`（mesh2）：601 个时刻 × 13 个接收点的三分量位移，单位 m，17 位有效数字。
  - 同名的 `*.field.csv`：每个时刻的最大 Green 应变和最小 J。
  - `solver.log`：时间步记录。
  - `.mph` 文件。
- **交回方式：** 把整个 `runs/` 文件夹打包发回，`.mph` 可以不带。我会转换成交付格式，并检查哈希、接收点顺序、时间网格、零初始状态和应变检查。

  也可以自己转换：

  ```sh
  python research/comsol-p1-20261024/local_kit.py collect p1-kit/runs --output p1-delivery
  python -m coarsegraph.comsol check p1-delivery --partial
  ```

- **自己建模时：** 按 [数据要求](comsol-data-request.md) 第 4 节交付。
  - 每次运行一个 40 列 CSV，文件名为 `<工况>_<本构>[_<变体>].csv`，至少 12 位有效数字。
  - 每个工况一个元数据 JSON。
  - 本构自检的三组 S 值。

## 6. 拿到结果后我会做什么

1. **复现检查：** 新线性与旧线性的差异，要求在 1e-6 以内。
2. **COMSOL 收敛：** dt2、mesh2 与基准的差异，重点看非线性增量的 2f。
3. **谱元核对：** 谱元标签与 COMSOL 的非线性增量 2f 对比，用 5% 门槛。
4. **重新训练：** 两者一致后，把 C 族加入训练，重新训练 4 阶、h 3 mm 的粗网格算子，并用留出工况重新验收。
